## 安装与启动

1. 打开项目的 [Releases](https://github.com/jitingcn/SlimeNRF-Helper/releases) 页面。
2. 选择版本。需要测试版时，选择标记为 **Pre-release** 的版本。
3. 在 **Assets** 下载对应平台的包。

需要开发构建时，打开 **Actions**，选择成功的 **Native no-firmware CI** 运行记录，再下载其中的 **Artifacts**。

Windows 下载文件名以 `windows-x64-no-firmware.exe` 结尾的包，下载完成后直接运行。该文件使用 UPX 压缩，可能引发安全软件误报或兼容性问题。不发布未压缩的备用版本；本地 Cargo 构建仍保留未压缩的原始可执行文件。

Linux 下载 AppImage。将以下示例文件名替换为实际下载文件名。在文件所在目录执行以下命令。

```bash
chmod +x ./slimenrf-helper-0.1.1-linux-x64-no-firmware.AppImage
./slimenrf-helper-0.1.1-linux-x64-no-firmware.AppImage
```

如果没有 FUSE，使用以下命令启动：

```bash
./slimenrf-helper-0.1.1-linux-x64-no-firmware.AppImage --appimage-extract-and-run
```

无固件包内置默认配置，但不包含固件载荷。更新时使用本地文件、远程下载或显式外部配置。Linux 的服务、设备权限与 UF2 挂载条件见 [Linux 设备与运行条件](#linux-devices)。源码构建见[开发与打包](DEVELOPMENT.zh-CN.md)。

<a id="first-use"></a>
## 首次使用

应用每次启动默认打开**首页**。通过**语言与外观**可进入设置。如果无法读取已保存的偏好，应用会改为打开设置，并保持原有文件不变。

选择**连接设备**，按指引检查连接：

1. 在**准备设备**中，准备接收器与 USB 数据线。给追踪器充电，并放在接收器附近。正常工作的设备不必先更新固件。
2. 在**连接接收器**中，将接收器插入电脑，观察设备状态。没有出现接收器时，换一根数据线或 USB 接口试试。
3. 在**检查追踪器**中，打开追踪器并轻轻移动，观察近期数据计数。然后选择**打开设备设置**，查看各接收器下的设备。

点击编号步骤，或使用**返回**和**下一步**浏览。不连接硬件也能查看每一步。前进到下一步不表示检查通过。本次运行中切换到其他功能后，指引会保留当前位置，但不会跨启动保存进度或完成标记。

首页通过现有只读 HID 监听展示接收器发现结果与近期传感器活动。有数据不代表配对、校准或 SlimeVR 设置已经完成。发现失败、接收器无法读取或正被其他任务使用时，状态区会说明情况，不将未知数据显示为零。

打开首页或浏览连接指引、更新方式选择与连接帮助，不会打开串口、发送命令、查询固件、开始录制或刷写设备。返回首页时，已授权的任务继续运行。选择**无线更新**卡片会打开已有更新页，保留上次使用的模式。ESB 模式会自动查询固件信息，Legacy BLE 模式不会。

熟悉操作后，可从侧栏直接进入**设备设置**、**固件更新**、**无线更新**、[**陀螺仪校准**](#gyro-calibration)、采集或分析功能。首页也可通过**设备设置**进入终端。在**设备设置**中选择设备，按需连接串口。发送终端命令或使用命令卡片前，先核对目标。已保存命令卡片和**直连串口批量**仍需预览与确认，终端的**全部发送**则立即提交。

连接失败时，打开首页的**连接有问题？**。这里说明接收器未发现、没有追踪器数据、串口占用和只连接 USB 追踪器的处理方法。Linux 还会显示设备访问权限说明。

更新时，先准备适配的固件、稳定供电和 USB 恢复路径。取消不能回滚已写入的数据或已发生的激活。

1. 进入 **固件更新** 或 **无线更新**。
2. 选择目标和对应固件。
3. 核对型号、角色、来源与风险。
4. 明确确认更新。
5. 更新完成后重新连接设备。
6. 核对固件版本。

分析数据时，在 **VQF 回放** 导入 `.slimecap` 或 CSV 与元数据配对文件。回放不发送设备命令。

## 设备与终端

应用按接收器分组显示追踪器和可靠关联的串口功能。未能可靠关联的串口单独保留。接收器与串口需匹配的 USB ID 和唯一非空 USB 序列号，追踪器直连与无线端点需唯一规范化设备地址。名称、tracker ID、频道不能证明同一设备。tracker ID 只在其接收器内有效。

终端命令使用**命令控制台**。标有**仅用于原始数据采集**的 CDC 端口是独立的数据接口，不是控制台。要使用该接口，打开**原始数据采集**。如果控制台不可用或关联有歧义，先检查 USB 连接并刷新设备列表，再重新选择。不要根据端口编号猜测用途。

- 启动自动枚举并只读监听主 HID，不自动打开串口、发送 `info`、校准或开始 raw 采集。进入 ESB 页会进行只读固件信息查询。
- 点击接收器名称、可用控制台端口名称、终端标签或在线追踪器卡片切换当前指令目标；勾选追踪器进入已选目标上下文。离线卡片不能加入命令选择，但身份唯一的离线配对设备仍可获得焦点以编辑昵称。唯一身份匹配且已连接的直连串口也可使卡片显示在线。
- 可显式连接，也可点击预制命令或在离线终端发送，由应用连接明确匹配的命令控制台后继续。连接固定为 115200 波特、8N1、无流控，并拉高 DTR 和 RTS。仅浏览和勾选不打开端口。
- 首次打开失败须显式 Retry/Cancel，不抢占、不跨通道重发。关闭占用该设备的其他程序或检查权限；原始错误保留。
- 成功连接过的会话可在观察到设备返回、进行一次异常断线探测，或 Windows COM 变更通知后的合格扫描后尝试恢复。恢复只使用原来已核实的控制台，不迁移端口、不重放命令，也不定时重试。没有新的合格证据时，手动重新连接。身份与扫描要求见[恢复准入](ARCHITECTURE.zh-CN.md#terminal-recovery)。
- **断开**、**停止重连**、关闭终端标签、设备操作资源移交和退出应用均撤销恢复。首次打开失败不会启用恢复。

每个端口独立收发，切换标签或功能页不关闭会话。**断开**会保留标签和终端文本。悬停终端标签，或按 Tab 聚焦其关闭按钮时，会显示 **X**，不改变标签布局。**X** 可关闭已连接、重连中或已断开的会话，清理完成后移除标签和文本。活动命令、设备操作或日志导出期间可能暂时无法关闭。关闭前先导出需要保留的文本。

终端支持有界回看、ANSI 颜色、跟随输出、跨行拖选、纯文本复制，以及每个端口最近 100 条命令的 ↑/↓ 回放。回放本身不发送命令。拖选暂停跟随，但后台继续接收。**导出日志**只保存点击时保留的 UTF-8 文本快照，不是持续文件日志、原始采集或完整 VT 屏幕仿真。

**导出日志**失败时，已有目标文件保持不变。

新终端标签默认开启**跟随输出**和**自动换行**。自动换行让长行适应终端宽度。切换标签或页面时，各标签保留你手动选择的状态。这些控件只改变显示，复制和导出仍保留文本原有的字节和换行。

按 Tab 聚焦终端文本后，可用方向键移动光标，按住 Shift 扩展选择。Home 和 End 移至当前显示行的两端，Page Up 和 Page Down 滚动终端。在 Windows 和 Linux 上，Ctrl+Home 和 Ctrl+End 移至保留文本的两端，Ctrl+A 选择全部保留文本，Ctrl+C 复制所选内容。键盘导航暂停**跟随输出**，但不停止接收。重新勾选**跟随输出**可继续跟随新数据。

TPS 是主机收到传感器记录的速率；近期没有数据不等于设备断电，不代表电量、信号或能力。串口写入完成不等于设备 ACK/执行完成。

**设备设置**页的在线追踪器卡片右上角显示最近通过 HID 上报的电量百分比和电压。没有有效电池数据时不显示数值，设备实际报告的 `0%` 则正常显示。设备离线或接收器槽位更换追踪器后，旧读数会清除。

卡片用紧凑的两行显示名称和硬件 ID，下方显示 TPS 与在线状态。**当前**和**已选中**标记位于右下角，不会改变卡片高度。

复选框只改变批量选择，与卡片主体切换当前目标的操作相互独立。点击已禁用的复选框不会改变选择或当前目标；点击身份唯一的离线卡片主体仍可打开该目标。

观察到配对变化后，应用会重新建立该接收器的追踪器列表，并清除失效的选择和固件信息。已保存的昵称仍然保留。如果在其他工具中修改配对后列表仍未更新，点击**刷新设备**。设备离线本身不会移除配对记录。

<a id="remembered-devices"></a>
### 记住设备与设置昵称

为当前查看的设备修改昵称：

1. 在**设备设置**中，点击接收器、追踪器卡片或身份已确认的直连追踪器控制台。
2. 在**命令 → 当前设备**面板顶部核对原始身份。
3. 点击铅笔，输入昵称，再选择**保存**。**取消**会丢弃草稿。
4. 清除昵称时，清空输入框，再选择**保存**。

切换设备、命令范围或页面会丢弃未保存的内联草稿。编辑昵称不会连接设备，也不会启用不可用的命令。如果面板显示**记住**，先选择它，再编辑昵称。身份不唯一的设备不会显示铅笔。

打开**设置 → 管理设备**，或使用设备配置页清单上方的**管理设备**。当前未观察到的已记住接收器与追踪器仍保留在列表中。

1. 根据原设备标签及 USB 序列号或 RF 地址核对设备，不只依赖端口或追踪器编号。
2. 选择**编辑昵称**，输入名称并**保存昵称**。**取消**不改变已保存的值。
3. 只移除昵称时，选择**编辑昵称 → 清除昵称**。
4. 移除设备保存的昵称和信息时，选择**忘记设备**，核对设备身份后确认。

无效昵称的反馈显示在草稿旁，不会被报告为存储故障。**取消**会清除草稿反馈，不改变已保存的值，也不会清除独立的存储问题。设备列表较长时，Tab 和 Shift+Tab 会让新聚焦的控件进入视野；焦点再次移动前，手动滚动位置保持不变。昵称输入框聚焦时，Home、End、Page Up 和 Page Down 仍按输入框的编辑语义处理。

昵称仅保存在本机，与原设备标签并列显示。忘记设备不解除硬件配对、不重置硬件、不发送命令、不断开会话，也不删除日志、录制、偏好或已保存命令。

忘记后，反复刷新设备不会立即重新添加。可在其**未记住**行选择**记住**，也可重启应用，或等应用确认设备已消失后再重新连接。发现错误或没有 TPS 本身不算确认消失。重新记住不会恢复已删除的昵称。

**当前已观察到**表示应用目前识别到设备，不代表设备已可接受命令。**当前未观察到**的记录仍可编辑。标为**上次上报**的字段是此前上报的描述，不代表当前固件能力。已保存记录不会连接设备。

追踪器的**上次所属接收器**显示本应用最近明确观察到该追踪器无线通信所经过的接收器。设备离线或应用重启后仍保留此信息。旧记录及只见过离线配对信息的追踪器，在应用观察到上述通信前不显示此行。离线配对列表与 USB 直连不会替换已保存的接收器。应用无法还原关闭期间的接收器使用情况。

此行使用接收器当前保存的昵称或原名称。文字被截断时，悬停可查看完整接收器身份。忘记接收器后，追踪器仍保留其 USB 序列号，但不再显示已删除的名称。此历史信息不代表在线状态，也不会启用命令。

待确认命令与已接受历史保留捕获时的目标标题，不随昵称或语言修改而改变。重新打开检查可使用新标题。原始终端输出、导出日志和录制身份保持不变。

无法唯一区分的设备不能设置永久昵称。支持的身份与技术限制见[已记住硬件与昵称显示](ARCHITECTURE.zh-CN.md#remembered-devices)。

## 命令与批量操作

命令按接收器或追踪器角色提供说明。未知角色仅显示通用信息与帮助。选择命令后，按实际参数规则填写并核对完整目标。校准快捷命令调用固件能力，与[陀螺仪校准引导](#gyro-calibration)分开。目录以固定上游串口契约为依据，不提供绕过现有身份、在线或路由检查的 HID、采集或 OTA 快捷通路。

命令按实际适用的任务分组展示，每个条目只有一个入口；`Device info` 与 `Help` 仅位于 `Information`，不在 `Diagnostics` 重复显示。`Diagnostics` 仅在目标支持该组实际诊断命令时出现；角色、作用范围或参数契约不同的命令仍各自保留。

点击分组标题可收起或展开该组命令卡片，默认全部展开。在本次应用运行期间，切换设备、命令范围或**历史**标签页后，各组保留原来的折叠状态。重新启动应用后全部展开。折叠分组不会修改命令参数，也不会发送命令。

直连和远程追踪器指令优先显示**系统**、**诊断**、**连接**、**传感器校准**和**磁力计**，随后显示**温度校准**和**重置**。直连追踪器还在**温度校准**前保留**信息**分组。远程排序适用于当前远程追踪器、所选追踪器和全部在线设备。接收器及角色未知的设备仍从**信息**分组开始。

- **已选追踪器：**逐卡勾选，预览每个 `send <slot> <command>` 后确认。同接收器不同槽位分别执行，不按串口去重。远程单卡/多选要求已知地址、唯一接收器串口及近期传感器活动；唯一已连接直连不受该无线活动门控。
- **全部在线设备：**接收器的 `Select all online` 只设定指令范围，随后确认 `send all <command>`。实际在线范围由接收器决定，不等于主机勾选子集或全部历史设备。
- **直连串口批量：**勾选串口行，在 `Direct serial batch` 输入命令，点击 `Review selected…`，待明确目标连接完成后再 `Confirm and send`。排除项不会自动改成广播。

填写参数前冻结目标。更换目标、选择或范围会撤销旧确认；身份、会话代次、槽位或路由变化后不能继续旧操作。`History` 保留逐目标排队、发送和失败结果；不会因失败自动换路由或重发可能有副作用的命令。

### 参数与高风险命令

- 频道范围 **0–100**；远程 channel/clearchannel 仅在明确接收器范围的 `send all` 提供，会影响接收器与在线追踪器，不能从槽位子集暗中扩大成广播。
- 加速度计校准是 **18 姿态**，不是旧六面流程；按当前固件操作说明执行。`meow`、TDMA 开/关等仍取决于设备实际固件。
- `sens` 要求有限 `x,y,z` 角误差或 `reset`，留空不是查询，会被拒绝。**远程**每轴限 `[-327.68,327.67]` 以满足 signed-centidegree 编码；**直连**只要求有限 f32 三元组，不套远程编码上限。实际接受的灵敏度仍取决于设备配置及非奇异增益，不是统一物理范围。`sensauto` 可选 x/y/z 与 1–100 圈，轴预设不指定圈数时采用设备默认。
- 远程 `teston` 可选 0–1000 TPS，留空/0 用设备默认，实际吞吐受设备能力限制；直连 teston 不附 TPS。不要用请求值当作实测速率。
- WOM enter 须确认，接受命令不等于已休眠。WOM timeout 留空为查询，0 为恢复默认，范围 0–35791。
- 远程 reset 仅提供 zro/acc/bat/mag/tcal/fusion 对应范围，不提供虚构的 reset sens/all；fusion 单独警告。直连 shutdown、resetfusion、testoff 仍须检查准确目标和风险。
- 远程 `tcal` 是**无参数加热启动**，须确认实验性物理加热风险、目标温度配置、外部供电和硬件条件；不提供虚构的远程温度参数、stop/status。发送成功不代表设备接受、加热开始或校准完成。温度曲线读取与导入不会启动加热。

<a id="saved-commands"></a>
### 使用已保存的命令与宏

#### 保存命令卡片

1. 在**首页**打开**管理命令**。
2. 选择**新建命令**。
3. 输入标题。
4. 按需添加描述或图标。
5. 每行输入一条命令。
6. 选择目标模式：
   - 只使用现有已连接控制台时，选择**已连接的终端**。
   - 向所选接收器发送原始命令时，选择**接收器控制台**。
   - 通过所选接收器控制在线追踪器时，选择**通过接收器控制追踪器**。
7. 如需在首页显示卡片，勾选**固定到首页**。
8. 选择**保存**。

最多输入 16 行命令。删除中间的空行，末尾回车不会增加步骤。

**通过接收器控制追踪器**模式下，输入不含 `send` 包装的命令。实际在线范围由接收器决定。

在命令库使用**编辑**、**上移**、**下移**、**取消固定**或**删除**维护卡片。取消固定保留命令及其顺序。内置首页卡片与命令目录保持不变。

保存失败时，处理提示的存储问题后再次选择**保存**。原命令库与编辑草稿仍然保留。

#### 运行已保存卡片

自定义命令的效果尚未验证。发送前检查命令和目标。

1. 打开固定卡片，或在命令库选择**运行**。
2. 接收器模式下，选择接收器。
3. 所选控制台未连接时，选择**准备所选控制台**。
4. 检查准确命令、端口、目标、排除项与风险提示。
5. 选择**确认并发送**。

要阻止后续提交，选择**停止后续步骤**。已经接受的写入无法撤销。**已写入**仅表示传输完成，不代表固件执行完成。失败的写入可能已传输部分字节。选择 **X** 可关闭已完成的命令结果。

#### 向已连接控制台发送终端输入

1. 在源终端输入命令。
2. 选择**全部发送**，立即向当前已连接且符合准入条件的控制台提交，无需二次确认。
3. 打开右侧命令面板的**历史**查看结果。发送不会自动切换标签页。

**历史**汇总所有终端标签页的**全部发送**结果，标明源终端，并保留已有预设命令历史。**全部发送**结果不再显示在终端控件下方或首页。选择**详情**查看逐目标结果与排除原因。发送期间，选择**停止后续步骤**可阻止后续提交。已经接受的写入无法撤销。发送结束后，选择 **X** 关闭结果。失败或被排除的结果会保留，直到手动关闭。结果列表已满时，关闭已完成的结果，或等待正在发送的命令结束。

**全部发送**不建立连接，也不重试失败的写入。已经断开的控制台不属于这次发送的目标。仅当至少一个目标接受提交且源文本未变时，才清空草稿。普通**发送**与回车保持单终端行为。

身份检查、逐目标失败、取消与不自动重试的规则见[已保存的自定义命令](ARCHITECTURE.zh-CN.md#saved-commands)。

## 校准追踪器陀螺仪

侧栏只有一个**陀螺仪校准**入口，内含**静止校准**和**逐轴灵敏度**两个选项。浏览、选择追踪器或切换引导不会启动校准。

1. 打开**陀螺仪校准**，选择一种引导。
2. 选择一个已知的 USB 追踪器或接收器下的在线追踪器。核对端口或接收器、槽位和追踪器身份。接收器本身、离线追踪器和未识别的串口设备不是校准目标。
3. 对于 USB 直连，在本页点击**检查连接**。检查会打开连接，查询身份、命令支持和当前参数，不启动校准。检查结束后，点击**返回准备**。无需先到**设备设置**连接串口。
4. 使用**静止校准**时，将追踪器放在稳定表面上，并保持静止。
5. 使用**逐轴灵敏度**时，选择传感器 X、Y 或 Z 轴，并填写 1–100 圈完整旋转，初始值为 5 圈。查阅电路板文档确认传感器轴，不要根据外壳边缘或按钮推断方向。与普通 `sens auto` 快捷命令不同，引导始终发送明确的圈数。
6. 点击**检查校准计划**。核对目标、任务，以及适用的轴和圈数。本次校准期间，不要使用其他校准工具或追踪器的校准按钮。点击**开始校准**。
7. 按固件提示操作。准备和静止采集期间保持静止。灵敏度校准先等待旋转提示，再沿同一方向完整旋转指定圈数，最后停止旋转并保持静止，等待验证。
8. 查看结果和**详情**。追踪器报告已应用后，可点击**完成**，或使用出现的**准备 Y 轴**、**准备 Z 轴**。这些操作会等待连接清理结束，再返回准备，不会启动下一轴。每一轴都需单独检查并启动。

切换页面不会停止运行或更换目标。**停止观测**只结束助手的观测，不会取消追踪器上的校准。命令可能已到达追踪器时，设备可能仍在校准，后续命令可能冲突或被拒绝。

连接清理结束后，可使用出现的**确认结果并继续**或**确认未知结果并继续**。确认仅允许继续使用助手，不改变设备结果，也不证明校准已取消或数据已保存。常规 USB 直连静止校准结果无需断电重启。可用时，**仅重新观测，不启动校准**会进行有时限的观测，不再发送校准命令。

普通 USB 直连静止校准的数据采集或排队不代表已应用。直连回读展示舍入后的当前值，无线路径无法回读最新系数。报告已应用不代表系数已存储。物理校准精度与存储持久性仍未验证。证据、观测和固件限制见[陀螺仪校准协议限制](PROTOCOLS.zh-CN.md#gyro-calibration)。

## 固件来源

本地文件、配置预设与内置成员是不同来源。无固件包省略内置镜像，但本地与远程来源仍可用。`Local` / `Remote` 只切换浏览视图，不清除有效分配。内置固件是固定版本，不自动追随上游。

打开固件更新页面后，可将一个固件文件拖到窗口或固件卡片上，也可继续点击**选择本地文件**。OTA 需要先选择固件分组。文件被拒绝时，之前选择的固件保持不变。加载文件不会开始更新。

远程应用目录提供 Tracker 仓库的 Releases（同时包含接收器资产），以及 Tracker 和 Receiver 的受支持成功 CI 产物。

下载引导程序时，选择**引导程序**，再选择**在线固件**。点击**引导程序发行版**或**引导程序 CI**。CI 来源列出仓库 `master` 分支的成功构建，只加载用于自更新的 UF2 文件。

点击 `Load versions` 或 `Latest available`，选择版本、精确板型和变种。下载包有多个成员时，需要明确选择一个。Latest 仅指该来源仍有可用产物的最新版本，不保证包含当前板型，不自动刷写，也不代表设备已是最新。

`Only matching boards` 和变种筛选只是帮助缩小列表，不替代板型、角色、格式、bootloader 和地址检查。当前可见变种为 Standard 与接收器 DataCollect (CDC)，不宣称存在 tracker DataCollect/HID 产物。HEX、UF2、MCUboot BIN、Secure DFU ZIP、Legacy DFU ZIP 不能改扩展名混用。

GitHub 令牌可选：启动前在进程环境设置 `GH_TOKEN` 或 `GITHUB_TOKEN`，优先非空 `GH_TOKEN`。公开 CI 优先 nightly.link，失败且有令牌才尝试有权限的 GitHub 下载。限流/过期/权限错误需解决后显式重试。不要把令牌放入配置、日志或问题附件。

来源记录保留实际可用的版本/commit、URL 与 SHA-256；上游未提供 digest 时本地计算的哈希不冒充上游认证。Release 日期编号、CI run 与设备 FW_INFO 版本不可直接比较；未知版本/日期不以文件修改时间推断。

## 更新步骤

### UF2

1. 若设备仍在运行，可直接在本页刷写盘列表上方选择命令控制台串口，点击**进入刷机模式**。已在设备设置中连接的串口会复用原会话，无须切换页面。
2. 等待设备进入 UF2 bootloader，刷新下方列表并核对卷标、路径与 Board-ID，勾选目标；重新插入不会自动重新勾选。
3. 选 `Application` 或 `Bootloader`，加载对应 UF2。bootloader 更新只支持明确匹配的 nosd 自更新包，要求已有兼容引导，不是裸芯片首次安装。nice!nano → ProMicro 预设是硬件转换用途，不能当作任意 clone 常规自更新。
4. `Review update` 核对目标、镜像、来源、哈希与风险，确认后才 `Confirm and start`。自动复制须另行勾选并确认，只适用于已选卷与镜像，不给新盘授权。
5. 完成后重新连接核对版本；Copy completed 只证明复制。换盘、重挂载或身份变更须重新选择和确认。

如果结果显示**复制待确认；尚未验证固件启动**，先重新连接并核对已安装的固件或引导程序版本，再决定是否重试。此结果表示主机已接受全部数据，但设备在写入收尾阶段断开，不能证明新固件已启动。

串口列表默认显示可用的 USB 串口和活动会话，用于识别检测到的端口，不显示终端会话是否已打开。其他可用端口可通过**显示其他串口**查看。原始数据 CDC 和关联有歧义的接收器端口仍被排除。选中后可查看系统提供的产品、制造商、USB ID、序列号，以及已连接设备报告的信息。无法可靠识别的设备须额外确认；新连接会在确认后才打开串口。连接或发送失败会在当前区域显示原因与可用的处理建议，不自动重发。该入口仅发送 `dfu`，不保证固件支持，也不会自动选择刷写盘或开始更新；Holyiot 仍使用下方专用流程。

`Exit DFU` 须确认所选卷，仅把该卷自身有效的 `CURRENT.UF2` 原样回写为 `REBOOT.UF2`。CURRENT 缺失/损坏即拒绝，不拿待刷镜像替代；复制成功不证明物理重启。

### Holyiot / OpenDFU

1. 选择 Holyiot 应用的命令控制台串口，确认 **Enter Holyiot DFU**。如果仍有命令正在发送，请等待完成后重试。检查通过后，应用等待原终端关闭再移交端口。
2. 重枚举后刷新，**手动重新选择 `Open DFU Bootloader` 端口**，不把旧 COM 当作新引导身份。
3. 加载对应 HEX 或 Nordic Secure DFU ZIP，检查预览后确认。默认 application base `0x1000`、hw `52`、app `1`、sd requirement `0`，其他 HEX 不会静默重定位；配置可提供适配参数。
4. 结束后重新连接核对版本。`nrf5_opendfu` 接收器自身不走 ESB，但仍可中继追踪器 OTA。

部分批次的 Holyiot 接收器无法通过指令进入引导模式。遇到这种情况，使用附带的磁铁轻触接口上方指示灯位置，切换到固件更新模式。然后从第 2 步继续。

开始 OpenDFU 时也会检查尚未完成的命令。拒绝本次尝试不会打断已接受的命令，也不会自动重试。

### ESB / HID OTA

1. **选择设备：**进入无线更新的 ESB 页，自动只读查询接收器和在线、地址已知的追踪器，不自动勾选。成功信息缓存 30 秒；持续停留不会定时轮询。可刷新整个接收器或单个失败追踪器；失败不因切页暗中重试。离页后已开始查询仍完成，明确取消才请求停止。
2. **选择固件：**按型号/角色组选择内置、本地或远程镜像，多成员包须明确选择。首次分组会尝试兼容内置镜像，不覆盖手动选择；无固件包不会反复预读缺失镜像。OTA 不更新 bootloader。
3. **查看映射：**核对每个接收器/目标、已安装信息及对应文件与来源，不根据命名推断升级/降级。Back/Edit 保留有效选择但撤销确认。
4. **确认更新：**最终检查冻结目标；先追踪器，后接收器自身，保留逐目标结果，不扩大为广播。结束后通过 `New update` 开始新流程，必须重新确认。

如果接收器显示**待核实**，保持供电。更新已经停止运行，但此结果不代表更新失败。后续设备扫描识别到同一接收器时，结果可显示**更新后已检测到接收器**。此状态和**接收器已响应**都不证明所选镜像或版本已经安装。点击**开始新的更新**返回设备列表。使用**刷新固件信息**查看已安装版本，再决定是否重试。

查询结果和离线已选镜像不是授权，提交仍须新鲜在线状态、身份与兼容性检查。普通页面查询只尝试一次，响应预算为 3 秒。执行前检查可按[ESB OTA 协议](PROTOCOLS.zh-CN.md#esb-ota)中的目标类型条件，对不完整查询额外尝试一次。进度采用 ACK 字节。VERIFY_OK、ACTIVATING 或写入成功不能代替 COMPLETE，COMPLETE 也不证明新固件已正常启动。无线更新失败时可连接 USB，在固件更新页恢复。

### Legacy BLE 与共同安全边界

设置开启 `Advanced features` 后才显示 Legacy BLE OTA。先手动让设备进入 Legacy BLE DFU，扫描并勾选实际设备，选择本地 Nordic **Legacy application ZIP** 或适配预设，预览确认；不提供远程选择。HEX 和 Secure DFU ZIP 不能替代 Legacy 包。关闭高级功能不能中断在途 BLE 任务。

未知板型的本地自编译镜像仅在其余检查通过后允许明确承担适配风险；已知冲突仍拒绝，未知远程目标拒绝更新。更新独占相关设备，等待排空、关闭、清理和 join，无关终端应继续运行，但真实多设备刷写连续性仍待验收。

**取消不回滚。** Cancel/关闭应用请求停止并等待释放，不能撤销已写入、已完成目标或激活。设备可能停留在 bootloader/部分更新状态；保持供电，检查逐目标错误并采用适配的 USB 恢复流程。完整物理传输、激活、重启版本与中断恢复尚未完成验收。

## HID 数据与事件

页面复用现有读取者，主/raw 接口分开，不因打开页面启动 raw 采集或让追踪器休眠。接收器、tracker ID、类别和事件类型多选筛选：同组“或”、组间“且”、清空为不限；筛选不发送命令。

显式选择接收器并订阅事件，应用查询能力、订阅并每 5 秒续订，ACK 最多等 2 秒。`停止全部事件订阅` 撤销本应用所有请求（包括断开/占用设备的恢复意图），不停止录制；未主动停止的订阅可在 OTA/raw 交还后恢复，不支持或失败需显式重试。操作 ACK 不冒充校准完成。

暂停显示只暂停列表，不停止文件录制。`保存近期日志` 冻结保留报文；`录制到文件` 独立连续保存，不受页面或显示筛选影响。`停止录制并保存` 排空、写 end 并同步，完成后可再次录制，拒绝覆盖已有文件。`.hidlog` 是本应用实际读写的 HID 原始记录，不是系统 USB 抓包、串口日志或 `.slimecap`；尚未支持离线播放/虚拟 HID。格式见[协议说明](PROTOCOLS.zh-CN.md#recording-formats)。

按 Tab 聚焦报文列表后，可用方向键选择报文，Page Up 和 Page Down 翻页，Home 和 End 移至筛选结果的首条和末条。导航时，所选报文会保持可见。

## 原始采集

1. 选择接收器的 **Raw HID** 或 **CDC binary data** 来源。CDC 列表只包含唯一识别的原始数据接口，不包含命令控制台或任意 USB 串口。接口存在不证明设备固件支持，主 HID 融合姿态不能当作原始数据流。
2. 选单追踪器或全部配对追踪器，设置请求速率。**单设备模式可能使同接收器其他配对追踪器休眠**，须明确确认；批量不是任意勾选子集。
3. 选择新的 `.slimecap` 并开始，查看预热、样本、预览及 Details 警告。停止后等待 STOP、尾部排空和 worker 结束，再打开回放。

单追踪器模式下，可先通过卡片查看在线状态和 TPS，再选择追踪器。活动描边随 TPS 变化。这里显示的是近期主 HID 数据速率，不是请求的原始采样率。已配对的离线追踪器仍可选择。采集期间显示冻结的目标身份，不显示过期的活动卡片。

如果没有采集来源，检查固件是否兼容以及 USB 连接，然后刷新。无法唯一识别原始数据接口时，CDC 不可用。

采集独占相关 HID/CDC，阻止相关命令/更新，切页不释放；无关设备应可继续使用。实机 START/ACK、吞吐、丢样、STOP、热插拔及连续性仍待验收。

## VQF 回放

导入 `.slimecap`、CSV + 同名 `.meta.txt`，或配对 ZIP，选择轨迹后自动后台计算；也可直接打开完成的采集。回放、参数编辑及导出不写回设备。

导入超出[录制限制](PROTOCOLS.zh-CN.md#recording-formats)的文件会被拒绝，包括单条 CSV 记录过大的情况。

- 顶栏分别控制加速度/磁力计校准、陀螺 None/Bias/Thermal 和是否使用磁力计，仅启用数据具备的校准。Parameters 按组提供 25 项 VQF 参数；有效编辑去抖重算，计算中旧结果不会冒充新设置结果。
- 左侧同步图表依观测/校准/开关显示，右侧姿态与诊断独立滚动；缺少温度/磁数据不画零曲线。悬停读数来自原始回放帧，不是抽稀线插值。
- 左拖曲线或使用底部滑条定位。Shift+拖动选择时间范围，Ctrl+滚轮缩放，普通滚轮滚动。图表工具栏也提供**放大**、**缩小**、**向前平移**、**向后平移**和恢复整段的控件，双击也可恢复整段。拖动模型旋转相机，滚轮缩放。模型获得焦点后，方向键旋转相机，+ 和 − 缩放，Home 重置相机。这些模型操作不会移动回放光标。
- 底栏支持循环、0.25–8×、6D/9D、逐样本、Robust/Full Y；裁剪极值有提示。未编辑输入且无待计算设置时可用 Space、方向键、A/B/X；切到其他应用继续播放，切本应用功能页暂停。
- 初次成功结果尝试一次 Auto A/B，也可手动 A/B/Clear 或明确重选。同文件重算保留有效参考与缩放，换源重置。Auto A/B 要求单连续分段、至少 60 秒，以及不同的合格静止区间；不满足就不部分应用。指标不是地面真值，跨滤波重置无连续漂移。
- 可选择内置参数，保存/重命名/删除自定义预设；Import YAML 严格合并部分 camelCase 参数，Export YAML 导出完整参数。YAML 不包含录制、校准、速率、参考或相机；录制通过**导出 ZIP**保存为 CSV 与配对元数据。损坏预设存储不会被静默覆盖。

**导出 ZIP** 取消或失败时，已有目标文件保持不变。**导出 YAML** 失败时也会保留已有目标文件。

内核/坐标/缺失数据与数值限制见[协议说明](PROTOCOLS.zh-CN.md)。姿态模型只是示意预览，不是精确 CAD 或完整校准工作区；不保证与运行设备逐位一致。

<a id="thermal-dump"></a>
## 温度校准曲线读取与分析

温度曲线提供已有**人类可读 `tcal dump`** 的独立只读分析窗口，不占用为未来温度校准助手保留的侧栏入口，也不是完整加热或校准向导。

1. 在侧栏打开**小工具 / Tools**，点击**温度校准分析 / Temperature calibration analysis**卡片，打开或聚焦唯一的分析窗口；主窗口仍停留在小工具页。没有连接设备也可在窗口内导入保存的 dump 文本；这个入口本身不发送命令。
2. 在**设备设置**的直连追踪器串口终端输入或点击预制命令 `tcal dump`，完整有效响应会自动打开或更新同一个分析窗口，不切换主窗口功能页、活动终端或设备选择。分析窗口内也可显式读取已经连接、角色已确认的**直连追踪器串口**；不会新开串口句柄、自动连接、远程广播、启动加热、校准或 raw START。不完整/错误响应明确提示，设备无点可正常显示空结果。
3. 宽窗口将 X/Y/Z 三张近方形曲线图并排，窄窗口上下排列；窗口较矮时向下滚动可查看统计和图例。共享温度 °C 视窗，每轴独立 bias °/s 纵轴。原始点为圆点，全局线性为绿线，局部 MLS 为蓝线，沿 MLS 的连续色带表示 ±0.01°/s，边界外推为虚线（最多各 6°C）；色带不是拟合置信区间。每轴就近显示 bias 范围及相邻点斜率平均/最大/最小值，图例标明拟合**残差平方和**。负温度不截到 0°C，点不足时不伪造拟合。
4. 窗口工具栏显示来源文件名，并保留导入、Zoom in/out、平移箭头、Reset view 与 `Save chart SVG`；SVG 使用三列布局，保存点击时冻结的分析与视窗，不会因选择保存位置期间数据变化而换图。关闭分析窗口不退出应用、不断开串口，也不取消已开始的读取；再次打开保留最近文档和视窗。退出主应用会关闭分析窗口，并沿用应用的设备任务清理流程。语言和主题跟随应用设置即时更新。

**保存 SVG 图像**失败时，已有目标文件保持不变。

固件控制台数字已舍入，dump **不是无损温度校准备份、原始二进制快照或可回写配置**。分析保留稀疏 slot 顺序；导入最多 512 点、slot 0–511，单行最多 4096 原始字节、响应最多 256 KiB，头/尾/行数必须一致。已启动但未完成的请求取消、超时或早期解析失败后，同端口进入隔离，须显式断开/重连；协议无 nonce，不能把迟到响应绑定到新请求。正常成功、TCAL 空响应或已经消费完整终止行的计数错误不要求因此重连。通用 `Command unavailable in this firmware` 不能证明 dump 已结束：在线读取继续等到原截止时间，若仍没有 dump 响应则失败并要求重连；离线导入可直接报告不支持。拟合仅为诊断，不写回设备；数学说明见[协议文档](PROTOCOLS.zh-CN.md#thermal-dump)。

<a id="rssi-scan"></a>
## RSSI 信道分析

1. 在**设备设置**的接收器串口终端执行 `rssi_scan`，或使用预制 **RSSI scan / RSSI 扫描**命令。收到有效测量后自动打开独立图窗，后续数据继续更新，不切换主窗口页面、终端或设备选择。
2. 横轴按实际信道编号排列，纵轴显示 RSSI（dBm）。数值越低，信道越安静。图中分别标记当前信道和接收器推荐的信道。悬停实测点可查看准确读数，也可用**上一个样本**和**下一个样本**持续显示所选信道的准确读数。这两个按钮会跳过没有测量值的信道。应用不会自动修改工作信道。
3. 也可从**小工具 → RSSI 信道分析 / RSSI channel analysis**打开图窗，导入保存的扫描日志（UTF-8 文本，最大 256 KiB）。关闭图窗不影响串口，再次打开保留最近结果；同次扫描的后续数据不会反复弹窗。

这里比较的是扫描期间各信道观测到的最强 RSSI，不是追踪器连接质量或平均信号。扫描时若有追踪器正在使用，正常通信也会使当前信道较活跃，不一定是外部干扰；图窗底部有相应提示。未测量和无效信道不补零；协议与数据边界见[协议说明](PROTOCOLS.zh-CN.md#rssi-scan)。

## Linux 设备与运行条件

需要可用 X11/Wayland、Vulkan 驱动/ICD、字体、用户 D-Bus 和文件选择器对应的 portal backend；Legacy BLE 还需 BlueZ、适配器与权限。AppImage 不能绕过这些条件，也不保证旧 glibc 或全部发行版兼容。

不要以 root 运行 GUI，或给所有 hidraw/tty 全员写权限。仓库可选规则只匹配接收器 `1209:7690`，管理员明确安装后重新插拔：

```bash
sudo install -m 0644 ./scripts/70-slimenrf-helper.rules /etc/udev/rules.d/70-slimenrf-helper.rules
sudo udevadm control --reload-rules
```

此命令从仓库根目录执行；仅下载程序的用户需另外取得[规则文件](../scripts/70-slimenrf-helper.rules)。`uaccess` 依赖本地桌面会话，不保证 SSH/后台/WSL ACL。其他 VID/PID 应精确配置规则或发行版串口组，组变更后重新登录；不执行全局 udevadm trigger。

UF2 需先由桌面挂载器/用户挂载为可写 FAT **块设备**文件系统；程序不自动挂载。临时 INFO_UF2.TXT 目录、网络共享、Windows 盘符或 `/mnt/盘符` 不能替代原生 Linux UF2 挂载。写前复核挂载实例，重挂载须重新选择确认。

WSL 构建的是 Linux 程序，GUI 需 WSLg 与渲染器；USB 还需转发、驱动及权限。WSLg 窗口可用不能证明 BLE、物理刷写、热插拔或原生发行版兼容性。发布与硬件验收要求见[CI 与发布门槛](DEVELOPMENT.zh-CN.md#ci-与发布门槛)。
